# blender/ — David Blackwell Hall exterior

`build_blackwell.py` builds the whole exterior of Blackwell Hall from `shared/blackwell_hall.json`,
the same spec the backend graph, nav grids and the frontend floor plan are built from. Nothing
about the building is typed in here twice:

| Spec data                        | Becomes                                                         |
| -------------------------------- | --------------------------------------------------------------- |
| `footprint` + each level's spaces| One clean solid per level (courtyard and podium garden are the holes the spaces leave) |
| `levels` (elevation, height)     | Floor stacking, roof height, parapet                            |
| Space kind behind each exterior wall | Facade: paired windows + staggered ochre panel (rooms), curtain wall (lounges, studies, kitchens), slot (stairs), small frosted (bathrooms), blank (corridors, lifts, risers, service) |
| Openings with `b == "outside"`   | Street doors and exits                                          |
| `outdoor` spaces                 | Ground courtyard paving, lawn, trees                            |
| Equipment `utility_feed`         | PG&E pad transformer on Durant Ave                              |

The ground floor solid is set back under a wood soffit, with storefront glazing on the outer
line, and the corner lounge becomes the glass bay at Dana St × Durant Ave, matching photos of
the real building.

## Running

The spec must be exported first (`cd backend && PYTHONPATH=. uv run python tools/export_building.py`).

**Headless** (the Microsoft Store install exposes `blender-launcher.exe`; a portable install exposes `blender`):

```powershell
blender-launcher.exe -b -P blender/build_blackwell.py -- --glb frontend/public/models/blackwell.glb --render blender/renders/hero.png --blend blender/blackwell.blend
```

Flags: `--glb <path>` export the building (not the site) as glTF binary · `--render <path>` render the hero
camera · `--blend <path>` save the .blend · `--no-site` skip streets, trees, neighbours. Relative paths
resolve against the repo root.

**Inside a live Blender** (Python console, or through the Blender MCP):

```python
exec(open(r"C:/path/to/Cal_Hacks_13.0/blender/build_blackwell.py").read(),
     {"HAVEN_ROOT": r"C:/path/to/Cal_Hacks_13.0", "HAVEN_ARGS": ["--glb", "frontend/public/models/blackwell.glb"]})
```

Both routes clear the scene first; a full build takes ~20 s and makes ~480 objects.

## Using the GLB in the frontend

`frontend/public/models/blackwell.glb` holds the `Blackwell Hall` collection only (levels, soffit, roof,
parapet, windows, doors, courtyard). The glTF exporter converts Blender's z-up to glTF's y-up, so a spec
point `(x, y, z)` lands at `(x, z, -y)` in three.js. Every window mesh is named `win_<space_id>` and carries
`space_id`, `level` and `kind` in its glTF `extras` (three.js exposes them as `mesh.userData`), so an R3F
view can tint a room's glass from world state (dark when its panel is dead, warm when lit) without any
geometry of its own. The glass material has an emission colour with strength 0, ready to be driven.

## Files

- `build_blackwell.py` — the script (bpy + bmesh only; no add-ons needed).
- `renders/` — hero renders (`hero.png` is the latest full-resolution render).
- `blackwell.blend` — saved scene, regenerated by the script; not hand-edited.
